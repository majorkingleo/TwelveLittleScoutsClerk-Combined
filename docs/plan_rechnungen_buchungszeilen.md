# Plan: Rechnungen Buchungszeilen zuordnen

> Erstellt von AI (GitHub Copilot / DeepSeek V4 Pro) am 2026-10-31.
> Status: **Plan** (noch nicht umgesetzt)

## Ziel / Anforderung

In **Operational** (und analog im **Events-Dialog**) sollen Rechnungen (Bills)
Buchungszeilen zugeordnet werden können:

- Unten gibt es einen neuen Tab **„Rechnungen"**.
- Eine Buchungszeile ist selektierbar, dann kann der Button **„Upload Bill"** gedrückt werden.
- Es öffnet sich der bestehende Rechnungs-Upload-Dialog (`UploadExternalBill`).
- Beim Speichern wird die Rechnung der selektierten Buchungszeile zugeordnet.
- Buchungszeilen, die bereits zugeordnet sind, werden farblich hervorgehoben.
- Im Operational-Dialog gibt es einen Filter für zugeordnete Buchungszeilen.

## Datenmodell: Junction-Tabelle `BILL2BOOKINGLINE` (n:m)

Mehrere Buchungszeilen können zu einer Rechnung gehören und umgekehrt.
Deshalb wird eine **n:m-Zwischentabelle** verwendet (analog zu
`DBBookingLine2Events` / `DBMembers2Groups`).

Die bestehenden Tabellen `BILLS` und `BOOKINGLINE` bleiben **unverändert**
(keine Versionserhöhung, kein neues Feld dort).

### Neue Tabelle `BILL2BOOKINGLINE`

| Spalte    | Typ         | PK | Index | FK                   | Beschreibung |
|-----------|-------------|----|-------|----------------------|--------------|
| `idx`     | INTEGER     | ✓  |       |                      | Primärschlüssel |
| `bp_idx`  | INTEGER     |    | ✓     | `BILLING_PERIOD.idx` | Abrechnungszeitraum |
| `bill_idx`| INTEGER     |    |       | `BILLS.idx`          | Rechnung |
| `bl_idx`  | INTEGER     |    |       | `BOOKINGLINE.idx`    | Buchungszeile |
| `bill_name` | VARCHAR(255) | |     |                      | Name der Rechnung (denormalisiert, Kopie von `BILLS.file_name`) |
| `amount`  | DOUBLE      |    |       |                      | Betrag der Rechnung (denormalisiert, Kopie von `BILLS.amount`) |
| `hist`    | DBHistory   |    |       |                      | Historie |

- **Sequence:** `B2B_IDX_SEQUENCE`
- **Version:** 1
- **FKs:** `FK_BILLING_PERIOD` (`bp_idx`), `FK_BILL` (`bill_idx`),
  `FK_BOOKING_LINE` (`bl_idx`) — alle NOT NULL.
- **Denormalisiert (nur fürs Debugging):** `bill_name` (Kopie von
  `BILLS.file_name`) und `amount` (Kopie von `BILLS.amount`).
- Optional (Performance): `bill_idx.shouldHaveIndex()` und
  `bl_idx.shouldHaveIndex()` zusätzlich setzen.

## Umsetzungsschritte

### 1. Neuer Bindtype `bindtypes/DBBill2BookingLine.java`

Muster identisch zu `DBMembers2Groups`:

- `extends DBStrukt`, `super("BILL2BOOKINGLINE")`
- `public static final String BILL2BOOKINGLINE_IDX_SEQUENCE = "B2B_IDX_SEQUENCE";`
- Felder: `idx`, `bp_idx`, `bill_idx`, `bl_idx`, `bill_name` (DBString 255),
  `amount` (DBDouble), `hist`
- `idx.setAsPrimaryKey()`, `bp_idx.shouldHaveIndex()`, `hist.setTitle(" ")`
- `addForeignKey(FK_BILLING_PERIOD, 1)`, `addForeignKey(FK_BILL, 1)`,
  `addForeignKey(FK_BOOKING_LINE, 1)`
- `setVersion(1)`, `getNewOne()` → `new DBBill2BookingLine()`
- Klasse als „generated by AI" markieren (Start/Ende-Markierung).

### 2. Registrierung in `Main.java`

In der bestehenden `getBindtypeManager().register(...)`-Liste ergänzen:

```java
root.getBindtypeManager().register(new DBBill2BookingLine());
```

### 3. `dialog_bill/UploadExternalBill.java` erweitern

- Neuer optionaler Parameter `preselectedBookingLineIdx`
  (Konstruktor-Überladung bzw. Setter; bestehende Konstruktoren bleiben erhalten).
- Beim Speichern (im selben `AutoMBox`, innerhalb der Transaktion):
  1. Rechnung wie bisher einfügen (`DefaultInsertOrUpdater`).
  2. Neue `DBBill2BookingLine`-Zeile einfügen:
     - `idx` = `getNewSequenceValue(DBBill2BookingLine.BILL2BOOKINGLINE_IDX_SEQUENCE)`
     - `bp_idx` = aktueller Abrechnungszeitraum
     - `bill_idx` = neue Rechnungs-`idx`
     - `bl_idx` = `preselectedBookingLineIdx`
     - `bill_name` = `bill.file_name` (denormalisiert)
     - `amount` = `bill.amount` (denormalisiert)
  3. `trans.commit()`.
- Event-Combo bleibt wie bisher (manuell wählbar, **keine** Vorbelegung aus
  der Buchungszeile).

### 4. Operational — `dialog_operational/Operational.java` + `.form`

- Neuer Tab **„Rechnungen"** im vorhandenen `jTabbedPane1`; Inhalt nur der
  Button **`jBUploadBill`** („Rechnung hochladen").
- Button nur aktiv bei genau **einer** selektierten Zeile
  (`jTContent.getSelectedRowCount() == 1`).
- Handler `jBUploadBillActionPerformed`:
  - selektierte Buchungszeile ermitteln
  - `UploadExternalBill(mainwin, null, bookingline.idx)` öffnen
  - `registerOnCloseListener` → `feed_table()` (aktualisiert Färbung)
- **Filter** neue Checkbox `jCBillAssigned` („Rechnung zugeordnet"):
  - in `filters`-Liste aufnehmen (Persistenz in `close()`)
  - in `feed_table()`: Links der Tabelle `BILL2BOOKINGLINE` laden
    (`where bp_idx = ...`), `Set<Integer> blWithBill` aus `bl_idx` bauen
  - wenn `jCBillAssigned` aktiv: SQL um `and idx in (ids)` ergänzen
    (leere Menge → `and 1=0`)
- **Hervorhebung** in `feed_table()`:
  - Zeilen mit `idx ∈ blWithBill` via `tm.setCellColor(...)` einfärben
    (Muster wie `BookingLine.colorBookingLineRow`, eigene Farbe z. B. hellgrün)

### 5. EditEvent — `dialog_event/EditEvent.java` + `.form`

- Im Tab **„Booking Lines"** neuer Button **„Upload Bill"**
  (`jBUploadBillBookingLines`), Single-Selektion auf `jTBookingLines`.
- Handler:
  - `UploadExternalBill(mainwin, event.idx, bookingline.idx)` öffnen
    (`event.idx` als Vorbelegung, wie beim bestehenden Bills-Tab-Button)
  - `registerOnCloseListener` → `feed_booking_lines()`
- **Hervorhebung** in `feed_booking_lines()`:
  - Links `BILL2BOOKINGLINE` für die geladenen `bl_idx` laden,
    `Set<Integer> blWithBill` bauen, betroffene Zeilen einfärben.
- Optional (separat zu entscheiden): Bills-Tab zusätzlich um Rechnungen
  erweitern, die über `BILL2BOOKINGLINE` mit Buchungszeilen dieses Events
  verknüpft sind.
